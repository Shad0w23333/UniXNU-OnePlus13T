## UFS 日志的风险（要你决定）

上机前只读查到：这颗闪存（三星 KLUFG8RHHD-B0G1）所有逻辑单元的 `bDataReliability` 都是 0。规范对这个值的说法是：写入途中掉电，**整个逻辑单元的数据都可能丢失**。`unixnu` 和安卓的 `userdata`、`super`、`persist` 都在同一个 LUN 0 上。

- **这不是这台手机特有的**：所有逻辑单元都是 0，是这颗闪存的出厂配置。安卓自己一直在往同一个 LUN 写数据，强制重启落在写入途中的情况同样存在。真实闪存有掉电恢复，这是最坏情况，不是常见结果，但规范不作保证，我也无法证明不会发生。
- **已做的缓解**：
  - 软件复位前先静默：抢下传输、补写最后一轮、刷缓存，然后才复位。
  - 按住电源键时写线程暂停，所以长按复位不会落在写命令上。
  - 亮度探针读没验证过的寄存器块之前，写线程也先暂停，读到挂死时线路上没有写命令。
  - 只在有新记录时写，约每 3 秒一轮，一轮几条命令。
- **剩下的风险**：看门狗咬合或固件复位这种没有任何前兆的硬件复位，恰好落在写命令上。

不想冒这个险就用“无 UFS 日志”包，代价是回到以前的取日志方式：必须在定时复位前长按，来不及就什么都看不到（今天两轮就是这样全丢的）。

## 之后：逐级打开新硬件

每一步一张镜像，出 FAIL、panic 或复位就停在那一步，下面的不做。有了 UFS 日志，大部分步骤可以自动跑，不用你操作。

1. **ADSP**（总闸）：只读 → 通电 → 完整启动。详细步骤 `build-userspace/a830-inputs/adsp-review.md`。
   - 第一步 `smem touch` 之后就 panic 的话，ADSP 这条路线到此为止。
2. **扬声器**：功放探测 → 接音频图 → 内核测试音（小声 440 Hz） → iOS 出声。
   - 第一次出声前默认限幅 −12 dBFS，不做长时间满幅测试。
3. **传感器**：先读手机上的配置，再开数据流（`sensors/build-report.md`）。自动亮度只能给粗略值，屏下光感要屏幕内容补偿。
4. **WiFi**：A、B 轮，再上协议栈的 C 轮，最后设置页 D 轮（`round-1101/wifi.md`，跑批 `工具/gpu-test-loop/wifi-rounds.py`）。
5. **手电筒**：干跑 → 点亮 0.3 秒 → 控制中心按钮（`torch/report.md`）。
6. **真熄屏**：`pagani-panel=1` 单独测 0x28/0x29。
7. **Metal 合并**：上游 AdrenoMetal 约 40 个提交，单独成包（`build-userspace/a830-inputs/upstream/merge-plan.md`）。
8. **可选**：自动锁屏、中文系统语言、放出定位服务（`seedvars/report.md`）；类 Linux 复位序列（`linux-like-reset/TESTPLAN.md`）。

## 要你同意才能做的事

- 上机测试（重启手机），以及开 UFS 日志。
- 从手机只读拉取文件：传感器配置、音频 ACDB 和功放容器（`haptics/sound/phone-readonly-checklist.sh`）。WiFi 固件不用拉：已确认在 `modem_a`，驱动能就地读；`/odm` 里的 `bdwlan.elf`、`regdb.bin` 可能要放进种子。
