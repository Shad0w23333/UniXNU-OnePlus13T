## 分区方案（512GB 机型，**尚未执行**）

作者的 `board.toml` 写的是 `first_lba = 44928768`、`last_lba = 61705983`，对应 256GB 机型的磁盘末尾。
**这组数值落在本机 userdata 的中间，绝对不能直接使用。**

初步计算（64 GiB，按 1 MiB 对齐，放在 LUN0 末尾）：

```toml
[userdata]
partition = "unixnu"
first_lba = 107409152
last_lba  = 124186367
lba_bytes = 4096
```

- userdata 会缩到约 394 GiB。目前已用约 153 GB，空间足够。
- 最终数值以官方脚本 `scripts/dual_sys/partition.py plan` 的输出为准。它会按 F2FS section 重新对齐，可能和上面的数值略有差别。
- 执行条件：
  - 要有能解密 /data 的 root TWRP，一加13T 上是否有还没查。
  - recovery 内核要支持 `F2FS_IOC_RESIZE_FS`。
  - 执行前先把个人数据备份好。
- 根卷只读，Data 放在内存里。系统盘镜像用 `fastboot flash unixnu unixnu-root.img` 写入，启动镜像用 `fastboot boot` 临时加载。

## 路线图

### 阶段 0：复现 build 63（部署现有成果）

1. 解决 UEFI 仓库问题。
2. 编译内核：本机或 Actions 二选一。
3. 运行 `ipsw fetch`，准备信任缓存、根卷策略和 RAM Data。
4. 依次运行 `firmware`、`payload`、`bootimg`。
5. 用 `partition.py plan` 生成本机分区方案，确认后执行缩容。
6. `fastboot flash unixnu`，再 `fastboot boot`。验收标准：进入锁屏，触摸可用，8 核在线。

### 阶段 1：Wi‑Fi（最快能做出贡献）

- 参考：renhiyama/pagani-linux 的 ath12k “peach” 系列补丁（约 600 行 QMI 改动，外加 pwrseq-qcom-wcn 上电时序）。
- 目标：给 `UniXNU/Ath12kWifi` 加上 `17cb:110e`（WCN7880）的硬件定义。
- 固件从本机 `/vendor` 导出，属于厂商文件，不要提交到仓库。
- 13T 设备树要补上 PCIe 根端口和 WLAN 的电源轨。
- 验收：扫描、关联、拿到地址、持续收发数据。

### 阶段 2：GPU（Adreno 830，主要目标）

**2026-10-29 新进展：作者已经做出 A830 Metal 候选版。**

- 作者分支 `codex/a830-metal-20261028`（设备仓库），云端第 68 次构建成功，产物已下载到 `作者产物/metal-68/`。
- 源码和专有固件打包成 `.ci-inputs/a830-metal.enc`（AES-256 加密，密钥只在作者的 CI 里），我们看不到 A830 后端源码，只能用编译好的内核和 Data。
- 内核里的 A830 流程由启动参数 `pagani-gpu=1` 触发，依次是：板级输入 → 上电 → 安全 CX → GPU SMMU → 固件内存 → GMU HFI → 命令处理器 → ZAP 退出安全模式 → 内存栅栏 → Metal 服务。失败时屏幕打印 `Pagani GPU stopped at <阶段>: <错误码>`。
- 四个 Gen8 固件已经编进内核；Metal 插件（Turnip + metal2vulkan）放在 Data 的 `ngpu/addons/`，并重新启用 iconservicesagent、WidgetRenderer、PosterBoard。
- 组装方法：`./unixnu payload --kernel metal-68/kernel/kernel.macho --owner-trust-cache metal-68/metal/owner-trust.bundle --data-ramdisk metal-68/metal/data.dbrdisk`，载荷要调到 192 MiB（带插件的 Data 有 40 MB）。
- 测试镜像：M 版（作者原配置：iPad 身份、4 GiB）、N 版（iPhone 身份、8 GiB）。
- 本机 GPU 固件已从 `/vendor/firmware` 备份到 `一加13T原厂备份/GPU固件/`（含 `gen80600_gmu.bin`），只留本地，不提交。

现有基础：

- 官方 `Adreno740` 和 `AdrenoMetal` 已经在小米平板 6S Pro（A740）上实现了 Metal 加速，链路是 Metal → AIR → SPIR-V → Turnip → IR3。
- `UniXNU-sm8750-common` 的 DTSI 已有 A830、Gen8 GMU、GPUCC 和 GPU SMMU 节点（默认关闭）。
- 社区分支 `NativeAdreno-myron`（SM8850，A8XX）有 Gen8 寄存器表。
- 一加 Ace 5 Pro（hummer）正在调 A830 探测，可以合作。
- Mesa 主线有 A830 的基础支持，社区 Turnip gen8 分支更完整。已知 GMEM 渲染会出问题，需要用 `TU_DEBUG=sysmem`。
- Linux drm/msm 对 A830 / Gen8 的支持可以当寄存器和上电时序的参考，具体合入版本待核实。

里程碑：

| 编号 | 目标 | 验收 |
| --- | --- | --- |
| G0 | 打开 sm8750-common 的 GPU 节点；GPUCC 时钟和 GX/CX 电源轨上电（用已有的 `Rpmh.h`） | 能从 RBBM 读回 chipid `0x44050001` |
| G1 | 加载 GMU 固件，完成 HFI 握手 | GMU 进入就绪，能提交功耗投票 |
| G2 | 加载 SQE/AQE，CP ring 初始化 | `CP_ME_INIT` 完成，NOP 命令能执行完 |
| G3 | zap shader 加载（需要 TZ/SCM 调用），GPU SMMU 上下文（ArmSmmu4K） | 安全模式切换成功，GPU 访问内存没有缺页错误 |
| G4 | fence、中断、BO / VM 管理（从 Adreno740 分叉出 Adreno830 后端） | 命令提交、完成、回收全流程跑通 |
| G5 | Darwin KMD 接入 A830 版 Turnip（先走 sysmem） | 离屏 Vulkan 测试用例通过 |
| G6 | AdrenoMetal 发布到 render server | 系统界面由 GPU 合成，卡顿消失 |

风险：

- zap shader 需要安全世界配合，在 XNU 里没有现成的 SCM 调用接口。
- Gen8 的 GMU HFI 和 A7xx 有差异。
- AirNir 离线编译器目前只面向 A740 的 IR3。
